# 2026-04-25 · 任务追踪日志（tracelog）

> 把每次任务的"完整执行细节"归档到 FS，供 Claude / admin / LLM 三方协同事后分析"为什么上次任务失败"。

## Context（为什么做）

DB（`project_task_event`）已经记了大部分事件，但**缺**：
1. 每轮 LLM 调用的**完整入参 messages 数组**（只记 count）
2. 每轮 LLM 的 **raw response**（含 token usage / tool_use 原始结构）
3. 注入到 prompt 的 **Skills 全文快照**（事后桶被改/删则重不了现场）
4. 召回的 **RAG 样本 full 文本快照**（同上）
5. **方便 Claude `cat` 的文件入口**（DB 不直观）

「执行详情」面板是给人看的概览；要让 Claude 真正能复盘任务，需要**结构化文件归档**。

## 设计原则

- **双轨**：DB 留作实时事件源（前端 WS 不变）；FS 在任务终结时归档
- **默认关**：`tracelog.mode=disabled`，admin 显式开启
- **可压缩**：终结后 `tar.gz`（省 70%+），admin 也可关掉留目录形式 `cat` 方便
- **自动清**：`retention_days` 后台扫，超期自动删
- **事件分诊**：超大事件（LLM 入参 / Skills 全文 / RAG 全文）路由到专属文件，不堵 events.jsonl

## 归档结构

```
${tracelog.dir}/task-{id}/
├── manifest.json               元数据 + 模式 + 最终状态
├── events.jsonl                全量 WS 事件（除路由到专属文件的）
├── system_prompt.md            完整 system_prompt 全文
├── llm_calls/
│   ├── call-001.json           { request_messages, response_events, model, elapsed_ms, success }
│   ├── call-002.json
│   └── ...
├── skills_snapshot/
│   ├── _common/SKILL.md
│   ├── uniapp-wot-h5/SKILL.md
│   └── uniapp-wot-h5/references/...
├── rag_snapshot/samples.json   召回 Top-K 的 full_amis_json + full_code 快照
└── analysis_input.md           👈 给 Claude / LLM 看的总索引（指向上述所有文件 + 排查切入点）
```

任务终结后 `compress=true` 时打包为 `${tracelog.dir}/task-{id}.tar.gz`，源目录删除。

## System Settings（前缀 `tracelog.`）

| Key | 默认 | 作用 |
|---|---|---|
| `tracelog.mode` | `disabled` | `disabled` / `smart`（仅失败任务详记，成功只留 manifest）/ `all_tasks`（全记） |
| `tracelog.dir` | `/tmp/amis-ai/tracelogs` | 归档根目录；prod 建议改 `/var/amis-ai/tracelogs` 持久化 |
| `tracelog.retention_days` | `30` | 后台 6h 扫一次，超期自动清；≤0 = 永久保留 |
| `tracelog.compress` | `true` | 任务终结后 tar.gz；关掉 = 留目录形式（cat 方便但占空间） |

admin 在「系统设置 → 任务追踪日志」分组可视化编辑。

## 新增 / 变更事件

| 事件类型 | 来源 | 落盘位置 | 说明 |
|---|---|---|---|
| `llm_call_snapshot` (新) | claw-agent-server `api_bridge.rs::stream` | `llm_calls/call-NNN.json` | 每轮 LLM 调用结束发 1 条；含完整入参 messages + 响应 events + elapsed_ms |
| `skills_content_snapshot` (新) | claw-agent-server `task_loop.rs` | `skills_snapshot/<bucket>/...` | 任务启动一次性发；含每个选中桶的 SKILL.md + references/*.md（每文件 ≤ 256KB） |
| `rag_samples_snapshot` (新) | backend `project_generation.rs::fetch_rag_extra_sections` | `rag_snapshot/samples.json` | 召回 Top-K 完整快照（含 full_amis_json + full_code） |
| `system_prompt_built` (已有) | claw-agent-server `task_loop.rs` | `system_prompt.md` | 路由特殊处理：prompt_full 写专属文件，events.jsonl 留精简版 |
| 其他 (text_delta / tool_use / tool_result / status_change / ...) | 各处 | `events.jsonl` | 默认 append 到事件流 |

## 怎么用（admin 操作步骤）

### 启用

1. 「系统设置 → 任务追踪日志」把 `tracelog.mode` 改成 `all_tasks`（或 `smart` 仅记失败）
2. 可选：把 `tracelog.dir` 改成持久化路径（如 `/var/amis-ai/tracelogs`）
3. 可选：调 `retention_days` / `compress`

### 复盘"上次任务为什么失败"

1. 在「项目工作台 → 详情页 → 执行详情」找到失败任务
2. 点 `📦 下载 tracelog 归档`
3. 解压：`tar xzf task-15.tar.gz && cd task-15/`
4. 把 `analysis_input.md` 喂给 Claude / LLM：
   ```bash
   cat analysis_input.md  # 先看总索引
   cat manifest.json      # 元数据
   cat system_prompt.md   # LLM 起步上下文
   ls llm_calls/          # 看几轮调用
   cat llm_calls/call-001.json | jq .  # 第一轮 LLM 推理
   ```
5. Claude 读完后给"根因 + 修复建议"

### 三方协作工作流

| 角色 | 看什么 | 干什么 |
|---|---|---|
| **人**（admin） | 「执行详情」+ 归档下载 | 决定是否启 tracelog；解压归档后给 Claude / LLM |
| **Claude**（你这种 IDE 助手） | `analysis_input.md` + `llm_calls/` + `system_prompt.md` | 给根因分析 + 修复 PR |
| **LLM**（`/api/projects/tasks/:id/analyze` 已有） | 同上（事件流 → meta-prompt） | 出"问题清单 + Skills 编辑建议" |

## 已知限制

- **smart 模式下成功任务只留 manifest**，事后想看完整流程必须用 `all_tasks`
- **配置缓存 30s TTL**，admin 改 mode 后最长 30s 才生效
- **打包靠系统 `tar`**（amis-ai 部署环境 WSL/Linux 都有），无 tar 时归档保持目录形式
- **tracelog.dir 默认 `/tmp/...`** 在 prod 重启会丢；持久化部署必须改路径
- **大文件（>256KB references）会以占位行替代**，事后需手动 `cat skills/<bucket>/references/<file>` 补
- **Anthropic 协议路径无独立 LlmRequestStart/End 事件**（这是历史问题，但 LlmCallSnapshot 已通过 wrap 覆盖了 Anthropic 路径）
- **claw-agent-server 重启后 LLM_CALL_SEQ 计数器重置**——如果一个任务跨进程重启，call-NNN.json 编号可能不连续
