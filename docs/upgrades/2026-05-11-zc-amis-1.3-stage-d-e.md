## 阶段 D 产出

发现一个**意外彩蛋**：前端 `CreateTaskModal` 是 1.0 起就完全 data-driven（拉 `listPlatforms()` + `listTemplates()`），所以注册到 `registry.yaml` 即自动出现在下拉。阶段 D 实际只需补齐 **维度枚举 + 多页面入口 + 桶激活兜底**。

### D.1 backend `builtin_platforms` 新增 zc-amis ui_lib

`backend/src/handlers/registry.rs:101-154` Web → React 下新增 `UiLibEntry { id: "zc-amis", name: "ZC 智搭 Amis" }`。让用户能在 React + zc-amis 维度组合下精准过滤 ZC 模板。

### D.2 `_common/SKILL.md` 更新过期引用

第 84 行的 `Skill({skill: "zc_amis"})` 是 B 阶段前的旧 skill 名。改成 1.3 现行的 `platform-zc-web`（自动注入）+ `zc-amis-schema`（按需检索 references），并列举 ZC 二开组件触发关键词。

### D.3 `CreateMultipageTask` 加 ZC tech_stack 选项

多页面任务页（`frontend/src/views/Projects/CreateMultipageTask.tsx`）技术栈下拉新增 `zc-editor-web` 选项。backend 收到后 `template_name = None → fallback 拼 "zc-editor-web-template"` 命中阶段 C 注册的 scaffold。

### D.4 `CreateTaskModal` 模板下拉显示 ui_libs tag

让用户在「选模板」时一眼看清 ZC 风格（zc-amis tag 用 magenta 突出）。

### D.5 修一个**多版本就潜伏**的 bug：`default_skill_buckets` 未生效

发现 `resolve_selected_buckets` / `claw-agent-server::select_buckets` 都按 `kind: platform/stack/ui` 三种维度选桶；而 `platform-zc-web` / `zc-amis-schema` 是 `kind: knowledge`，**维度 selector 命不中**——意味着选 ZC 模板时这两个核心桶不会被自动激活。

**修复**（最小破坏）：
- `resolve_selected_buckets` 新增第 4 个参数 `template_defaults`，在 explicit 路径未走时把 `template.default_skill_buckets` 也加入 selected
- `resolve_skills` handler 从 `state.template_registry.get(template_name)` 取出 `default_skill_buckets` 传入
- `project_generation.rs` 入库 `selected_skill_buckets` 时同样兜底：用户无显式指定则用 `template.default_skill_buckets`

> 注：`claw-agent-server::skills.rs::select_buckets` 同样未走 default_skill_buckets，但因为 backend 现在把 `selected_skill_buckets` DB 字段写入了 template defaults，等于通过显式路径绕开了 claw-agent 端的同问题。如果未来 claw-agent 启动时不读 DB 字段而是从 API 重算桶，需要在 claw-agent 端做同样修复。

## 阶段 E.2 runner 扩展

`eval/multipage-1.2/runner.py` 加两个 CLI 参数：

- `--tech-stack <name>`：默认 `uniapp-wot-h5`；1.3 用 `zc-editor-web`
- `--prompts-file <path>`：默认 1.2 路径；1.3 用 `eval/zc-web-1.3/prompts.json`
- 输出 `results-*.csv` / `results-*.md` 自动落在 `--prompts-file` 同目录

# 仅跑 R4 + R2（最关键的 2 个策略）= 6 任务，约 20 分钟
