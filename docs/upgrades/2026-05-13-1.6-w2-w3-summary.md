## 二、W3 fix · 修 task 340 冷启动超时

### 异常诊断闭环

W2 mini v2 报告标记：B 组 rs1 (task 340) 无 `rag_samples_injected` event。

backend log grep：
```
WARN ... RAG search 调用失败: error sending request for url
(http://localhost:8000/internal/search-code-samples): operation timed out
```

根因：**embedding 模型 (ollama qwen3-embedding:4b) 首调加载需 5-10s**，3s timeout 撞冷启动。评测连续启 task 时第一条易超时。

### 修复（commit 340123d）

[backend/src/handlers/project_generation.rs](../../backend/src/handlers/project_generation.rs):

```rust
// 1.6 W3：从 3s 提到 15s — 评测期冷启动实测 task 340 在 3s 超时
//         （embedding 模型 ollama qwen3-embedding:4b 首调加载需 5-10s）
//         15s 对线上稳态调用仍足够"快失败"，对冷启动留余量
.timeout(std::time::Duration::from_secs(15))
```

负例 search 同步从 3s → 15s（保持一致 + 同样有冷启动风险）。

### 验证

待 backend 重启加载新代码后下次评测自然验证（首任务不再超时）。线上稳态命中缓存时 < 1s 完成，15s 仍是"快失败"语义。

## 三、W3 enhance · CSV 加 failed_pages_brief 列

[runner.py:collect_metrics](../../eval/multipage-1.2/runner.py) 加一段：

```python
failed_pages_brief = psql(f"""
    SELECT COALESCE(STRING_AGG(
        route_path || ':' || REPLACE(LEFT(COALESCE(error_msg, ''), 60), '|', '_'),
        ' | ' ORDER BY page_idx
    ), '') FROM project_task_page
    WHERE task_id = {task_id} AND status = 'failed'
""")
```

CSV 新列 `failed_pages_brief` 内容示例：
```
/assets/repair:session 256d8135-... 终态=failed
```

后续评测出现失败 case，直接看 csv 这列就知道哪个 page + 啥原因，无需查 DB。
