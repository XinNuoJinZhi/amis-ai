## 一、问题与目标

**1.4 B.3b** 已落地 page 级评委（`spawn_judge_for_page` → 写 `project_task_page.page_quality_verdict`），但当 verdict=bad 时**仅入库 verdict，未自动回流为 code_sample 反面教材**。当时代码注释明确「让 admin 决定…手动操作，不自动」——出于"避免低质 negative 污染召回"的保守判断。

1.6 W1 的目标是把这条飞轮闭环最后一公里接通，前提是**不一脚到位全自动**：
1. 加 confidence 阈值（LLM 多吐一个 0-1 字段，低于阈值不入库）
2. 加总闸 `rag.judge.auto_page_negative`（默认关，admin 显式开）
3. 入库状态用全新的 `pending_review`（独立于 sample 级 `pending`），让 admin 抽审确认后才走 `approve / reject` 转 `approved / rejected`
4. 入库行带 `is_negative=true`、`source_page_id` 溯源，方便 admin 看是从哪条 page 来的

这样 1.6 W1 落地后：
- 总闸默认关 → 与 1.5 行为完全一致（**零回归风险**）
- 总闸开 → bad page 不会污染 approved 飞轮（pending_review 不进检索）
- 高 confidence 的 bad 才入库 → 噪声有阈值过滤
- admin 在前端按 status=pending_review 抽审，确认就转 rejected（保留 is_negative=true 让 search_negative_samples 召回）

## 三、Setting 新增 key

```
rag.judge.auto_page_negative              = 'false'      # 总闸
rag.judge.auto_page_negative_min_confidence = '0.85'     # 阈值
rag.judge.auto_page_negative_kind         = 'structural' # 入库 negative_kind 默认值
```

设计要点：
- 总闸默认 false → 1.6 上线后行为与 1.5 完全一致
- min_confidence=0.85 偏严 → 先观察 admin pending_review 通过率再调（高了入库少，低了入库多）
- negative_kind 默认 structural → 与 sample 级 auto_negative_on_bad 一致，避免误用 stylistic 引发 LLM negation blindness

## 四、新增 status 值：`pending_review`

| 状态 | 语义 | 是否进 RAG 召回 |
|---|---|---|
| `pending` | 采纳/手动入库未审 | 不进（only_approved=true 过滤） |
| `pending_review` | 1.6 新增：page-bad 自动入库待 admin 复核 | 不进 |
| `approved` | 审核通过 | 进 |
| `rejected` | 审核拒绝（保留 is_negative=true 进 search_negative_samples） | 不进正向，进负例 |

admin 工作流：
1. `GET /api/code-samples?status=pending_review` 看待审列表
2. 看 page → 确认是反例 → POST `/api/code-samples/:id/reject`（保 is_negative=true 进负例池）
3. 误标 → POST `/api/code-samples/:id/unmark-negative` + reject 或 delete

## 五、page judge prompt 改造

旧 prompt 只要 `verdict + reason`。新增 `confidence`：

```json
{
  "verdict": "good" | "needs_review" | "bad",
  "reason": "一句话解释（<=200字）",
  "confidence": 0.0  // 1.6 W1 新增；范围 [0,1]，缺省视作 0.5
}
```

- LLM 不输出 confidence 时容错回退 0.5（< 默认阈值 0.85 → 不入库，保守）
- 旧调用方（admin 手动评一条 sample）不受影响——sample 级 prompt 不变

## 六、入库逻辑（quality_judge.rs spawn_judge_for_page）

```text
write page_quality_verdict → if verdict=bad:
  read setting rag.judge.auto_page_negative
  if disabled → return
  read setting rag.judge.auto_page_negative_min_confidence (f32)
  if confidence < threshold → log info "below threshold" + return
  build code_samples row：
    tech_stack / platforms / tech_stacks / ui_libs ← task
    full_amis_json ← page.amis_json
    full_code ← ''  (page 级负例只评 schema，没代码)
    amis_json_summary ← f"[auto page-bad] {page.route_path}: {reason}"
    code_summary ← null
    status = 'pending_review'
    is_negative = true
    negative_kind = setting.auto_page_negative_kind
    rejection_reason = reason
    source_task_id = page.task_id
    source_page_id = page_id    ← 1.6 新增列
  INSERT
  spawn_vectorize(sample_id, summary_text)
  audit (operator_kind='llm_judge', action='auto_create_negative')
```

## 八、回滚

总闸关掉即回滚（不入库新行）。已入库 pending_review 行手工 DELETE 即可（不会污染 approved）。
