## 二、1.6 候选方向（7 选 3-4 排序）

### A. **C 项 page-bad 自动入库**（飞轮闭环最后一公里）
**痛点**：1.4 B.3b 评测显示 bad page 评分回填到 page_quality_verdict 但**没自动进 code_samples 作反面教材**。
**方向**：
- `spawn_judge_for_page` 在 verdict=bad 时检测 `rag.judge.auto_page_negative` 总闸
- 自动 `INSERT INTO code_samples (is_negative=true, negative_kind='structural', source_task_id, source_page_id, ...)`
- 抽取该 page 的 amis_json 作 `full_amis_json` + 触发 keyword_extractor + embedding 入库
- search_negative_samples 后续可召回这些"页级反例"，喂给 LLM 当 anti-pattern
- 加阈值（confidence ≥ 0.85）+ admin 抽审 workflow（先 status=pending_review，admin 确认才生效）
**估时**：3-5 天
**前置依赖**：观察 1.5 业务一段时间，看 page-bad 真实率（避免低质负例污染召回）

### B. **D 项压力集升级 — 召回敏感样本**（让 B.1 真实价值显化）
**痛点**：1.5 W1.3 现 9 prompts × 27 pages 全 100% 通过（B 组 33 hits / A 组 0 hits 仅在 keyword_hits 显化，但下游 LLM 没把"不同样本组合"翻译成"不同生成结果"）。
**方向**：
- 设计 **召回-敏感**样本：amis 里要求特定 ZC 二开组件（如 `modeltable` + `report-forms` + `flowCreate` 三件套），但样例库**只有部分**含此组合
- B 组靠 keyword 命中 ZC 样本 → 生成正确 ZC 模板代码
- A 组只靠 cos_sim → 拉到普通 crud 样本 → 生成普通 antd Table，运行时报错（如 `report-forms is not a function`）
- 设计 5-8 个这类 prompts 加进 `eval/1.5-rag-stress/prompts.json` 或新开 `eval/1.6-recall-sensitive/`
- 跑 A/B 对照，期望页通过率差 ≥ 10pp
**估时**：1 周（设计 prompts + 跑 baseline + 分析）
**前置依赖**：无

### C. **1.5 W2/W3 数据观察期 + 启用 A/B 实战**（消费已有投资）
**痛点**：1.5 W2/W3 框架都已落地但默认关，需要真实数据 50-200 任务积累后验证。
**方向**：
- **观察期**（前 1-2 周）：让业务跑，admin 用 `/api/admin/ab-compare`（即使没开 A/B 也能看单桶汇总）观察 actual_cost 分布
- **W2 校准**：跑 100+ 任务后看各 category 的中位数 actual_cost，调整 `estimate_calibration_factor`（如果误差 < 30% 可调小系数）
- **W3 启动 A/B**：admin 配 `category_tier_overrides_json_b`（B 组用更激进的 frontier 偏置 vs A 组 strong）→ 开 `ab_test_enabled=true` → 跑 2 周 → 看 cost_per_success_k 选优胜
- 整个过程做记录文档 `docs/upgrades/2026-05-XX-1.6-data-driven-tuning.md`
**估时**：观察 2 周 + 调优 1 周 = 3 周
**前置依赖**：业务在跑（不需要新开发）

### D. **E 项 桌面端 Tauri 模板**（扩平台覆盖）
**痛点**：1.5 已有 Web + Mobile（H5）+ 小程序，但客户偶尔要 PC 客户端。
**方向**：
- `scaffolds/tauri-vue3-template/` + `amis-ai-sandbox:tauri-rust-node20` 镜像
- 主进程 Rust，渲染进程复用 Vue3 + Element Plus（1.4 落地的）
- skill 桶：`platform-desktop` + `stack-tauri`
- 评测加桌面侧菜单 / 多窗口 / 文件对话 / 系统托盘 等场景
- IPC 模式：amis schema → Tauri command 调用约定
**估时**：3-4 周
**前置依赖**：Vue3 模板（1.4 已有）

### E. **Admin UI 可视化数据消费层**（让 1.5 数据可见）
**痛点**：1.5 W3 admin /ab-compare endpoint 写好了但没前端，W1.2 双 cost 列 / W2 estimate vs actual 对比也都没有展示。
**方向**：
- 前端 admin 加 `cost_per_success_k` 趋势图（按 category × 周聚合）
- A/B 对比 dashboard：variant a/b 三轴对比（成功率 / 平均 cost / 平均耗时）
- task 列表加 actual_cost_tokens / accumulated_cost_tokens / ab_variant 列（admin 视角）
- estimate vs actual 误差散点图（per category），辅助校准 calibration_factor
**估时**：1-2 周
**前置依赖**：C（要有数据才能展示）

### F. **F 项 Skills Marketplace MVP**（1.5 留作 1.7）
**痛点**：1.2 引入 `SKILLS_PLUGIN_PATHS` 只支持挂载本地目录，无包管理 / 版本 / 发现。
**方向**：
- 定义 skill 包格式（tarball + manifest.json 含版本 / 兼容性 / 作者）
- 加 `/api/skills/marketplace` 列已发布包 + 安装命令
- 私有 nexus / S3 兼容存储 + 包签名校验
- RBAC：组织内私有桶 vs 公开桶
**估时**：4 周
**前置依赖**：1.5 Skills 标准协议（已有）

### G. **工程化收尾**（兜底质量）
**痛点**：1.5 新功能（dual_route 切换 / ab_compare endpoint / accumulated_cost 累加 / multipage RAG fix）都没进自动化测试，下个版本回归风险大。
**方向**：
- smoke-test.sh 加：
  - 切 dual_route=false 跑一个任务 → 看 rag_samples_injected event 的 keyword_hits 为 0
  - 调 GET /api/admin/ab-compare 返回非 5xx
  - 多页任务跑完后 actual_cost_tokens > 0 且 accumulated_cost_tokens > 0
- regression-checklist.md 加 1.5 新功能人工回归项
- CI（如果有）加 cargo check + smoke-test 闸门
**估时**：2-3 天
**前置依赖**：无

## 三、推荐路径

**最高 ROI 顺序**：

1. **A（page-bad 自动入库）** — 3-5 天，飞轮闭环最后一公里，技术债清零
2. **B（D 压力集升级）** — 1 周，让 1.5 W4 修的 B.1 真实价值显化（不显化 = 没人信修了多大 bug）
3. **G（工程化收尾）** — 2-3 天，1.5 新功能进自动化测试，防 1.7 回归
4. **C（数据观察 + W2/W3 调优）** — 3 周并行（业务跑着不影响开发）

**1.6.0 scope 建议**：**A + B + G + C 并行**，总估时 2 周开发 + 3 周数据观察。

**1.6 候选副选**：E（admin UI）依赖 C 数据 → 等 1.6 中后期再开
**1.7 候选**：D（桌面端，3-4 周）+ F（Marketplace，4 周）+ E（如 1.6 没接）

## 四、跨版本风险

| 风险 | 应对 |
|---|---|
| page-bad 自动入库（A）可能引入低质 negative 污染召回 | 加 confidence ≥ 0.85 阈值 + status=pending_review 人审兜底，不全自动 |
| 召回敏感样本（B）设计需要细致功底 — 设计不好可能"看起来刁钻实际两组都过/都挂" | B 组期望命中 ZC 模板 / A 组拉普通 crud；先跑 1 个 prompt 看 keyword_hits 差异再批量设计 |
| A/B 启动（C）后 B 组配置出错会让一半用户体验降级 | A/B 默认 50/50 切 user_id，可以让先 1% / 99% 开两天观察再放量 |
| Tauri 模板（D）涉及主进程 Rust + 渲染进程 Vue 跨语言 IPC，调试链路长 | 1.7 候选，先验证 1.6 三轨 ROI 再决定 |
| 工程化 smoke（G）加复杂 case 会拖慢 smoke 总耗时 | dual_route 切换跑 1 个任务 ≈ 30s，多个新 case 加进去预计 +2 分钟，可接受 |

## 五、不做的事

1. **不做 D 项的 dual-route 升级到严格 RRF**（1.5 W4 实证单路 + bonus 已够用，且 bug 修了才生效 — 留 12 月观察）
2. **不做 prompt-engineering 大改**（1.4-1.5 集中在路由 + 召回 + 评测，下次改 prompt 应基于业务数据驱动）
3. **不主动开 A/B 而不灰度**（W3 框架支持 50/50，但 1.6 启动建议先 1%/99% 看 2 天）
4. **不做 ZC 之外的二开生态扩展**（ZC 已稳定，下个二开伙伴等 F Marketplace 落地后接入）
