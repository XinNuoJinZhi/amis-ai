## 1. 背景与目标

### 1.1 ZC Amis 是什么

ZC 智搭低代码平台基于 **baidu/amis 6.8.0** 做了二开（npm 私有版本后缀 `-my324v2`），包托管在 ZC 内网 nexus `app.xinnuojinzhi.com:8081`。资产分两部分：

1. **`~/Working/TianXing/amis-codegen/.claude/skills/zc_amis/`**（194 MB）
   - `assets/packages/`：ZC fork 的 amis monorepo（7 个 amis-* 核心包 + office-viewer 112 MB）
   - `assets/examples/` 50 MB：业务示例
   - `references/components/` 155 个 Amis 官方组件 md（文档轨参考）
2. **`~/Working/TianXing/amis-codegen/apps/`**（两个真实联调过的底座）
   - `zc_editor`：Web 端，React 19 + UmiJS + Ant Design Pro + Amis 嵌入 + 自研 `codegen-components` 15+ + `engine`（crud/form/relation）
   - `zc_uniapp`：小程序端，UniApp + 芋道商城模板（pages 含商品/优惠券/活动/聊天等业务模块）

### 1.2 1.3 目标

让 amis-ai 既会生成原生 Amis 风格代码，也会生成 ZC 智搭低代码平台特化版代码——把 ZC 资产**直接融入主仓**（不走插件包），用户在创建任务时能选「ZC Web 模板」或「ZC 小程序模板」。

### 1.3 切片

| 版本 | scope | 完成标准 |
|---|---|---|
| **1.3.0** | ZC 知识灌库（双轨）+ `zc_editor` Web 底座移植 + 反向飞轮支持「ZC Web 模板」出码 | 用户给 ZC Amis JSON → 系统在 sandbox 生成 zc_editor 风格 React 代码 + 启动 dev server 验证可访问 |
| **1.3.1** | `zc_uniapp` 小程序底座移植 + 反向飞轮支持「ZC 小程序模板」出码 | 同上，对应小程序端 |

**本文档 scope = 1.3.0**。1.3.1 用同一份知识灌库 + 加一个底座，沿用 1.3.0 的工作流。

## 2. 工作流程（1.3.0，5 阶段）

### 阶段 A：ZC 二开点摸底（1-2 天）

**目标**：搞清 ZC fork 的 baidu/amis 6.8.0 相对原版动了哪些地方（新增组件 / 修改 prop / 行为变化 / 删除）。

**做法**：
1. clone `baidu/amis@v6.8.0` 到本地比对源（**只读，不入 git**）
2. 用脚本逐文件 diff `assets/packages/{amis,amis-core,amis-ui,amis-editor}/src/**/*.{ts,tsx}` vs 原版
3. 抽取「ZC 特征」：
   - 新增 `.tsx` 文件（ZC 自加组件）→ 类型轨候选
   - 修改 schema interface（`@props` 字段增删）→ 类型轨 patch
   - 修改组件 render 逻辑（业务行为变化）→ 文档轨笔记
4. 输出 `docs/zc-amis-diff-report.md`：列清「新增 N 个组件 / 修改 M 个 prop / 行为变化 K 处」

**关键判断**：ZC 是「轻量魔改」（10-20 个二开点）还是「重度 fork」（100+ 二开点）？这个数字决定阶段 B/C 工作量。

### 阶段 B：ZC 知识双轨灌库（2-3 天，沿用 1.1 模式）

**目标**：把阶段 A 摸出的 ZC 二开点变成 Skills/RAG 知识，让 LLM 选「ZC 模板」时能拿到准确组件定义。

**两轨：**

1. **类型轨**：`skills/zc-amis-schema/`（新桶）
   - `SKILL.md`：桶 metadata（kind=schema, scope=zc-amis, priority=...）
   - `references/zc-<component>.md`：每个 ZC 二开组件一份 schema 描述（覆盖 prop 类型 / 默认值 / 子组件约束）
   - 数量预期：**ZC 二开组件 + 修改过的原版组件 ≈ 30-80 个**（看阶段 A 结果）
   - 复用原版 Amis 的组件不重复落，让 LLM 同时引用 `amis-core-schema`（原版）+ `zc-amis-schema`（ZC 增量）

2. **文档轨**：`code_samples` 表 + `zc-amis-1.3` 标签
   - 从 `assets/examples/` 业务示例 + `zc_editor/src/codegen-components/` 实际用法抽样
   - 数量预期：**80-150 条**（参照 1.1 灌 148 条 Amis 样例）
   - LLM 生成 ZC 风格时，RAG 按 `zc-amis-1.3` 标签硬过滤召回（沿用 1.2 strategy filter 机制）

3. **Skills 桶组合**（新增/扩展）：
   - 新增 `platform-zc-web` 桶：ZC Web 平台特有规则（路由约定 / 数据接口约定 / 业务模型）
   - 复用 `stack-react` + `ui-antd`：zc_editor 是 React + Antd 栈，没必要重写
   - `_common` 加一段「ZC vs 原版 Amis 何时选哪个」的判定规则

### 阶段 C：zc_editor 底座移植 + sandbox 镜像备 ZC 包（2-3 天）

**目标**：让 sandbox 容器能 `pnpm install` 不联网拉到 ZC 私有 npm 包。

**做法**：
1. 准备 ZC 包离线 tgz：
   - 从 `app.xinnuojinzhi.com:8081/repository/amis/` 一次性下载所有 `*-my324v2*.tgz`（约 7-8 个核心包）
   - 放到 sandbox 镜像 build 上下文：`shared/docker/sandbox/zc-web-node20/zc-packages/`
2. **新增 sandbox 镜像** `amis-ai-sandbox:zc-web-node20`：
   - 基于现有 `node:20-alpine` + `npm install -g pnpm@9.15.0`（沿用 1.2 修复）
   - `COPY zc-packages/*.tgz /opt/zc-packages/`
   - `RUN npm config set @amis:registry file:///opt/zc-packages/` 之类的离线 install 桥（具体方式待 sandbox 工程师拍）
   - 或：装一个**本地 verdaccio**，把 .tgz 自动 publish 到 localhost npm registry（这条最稳但镜像大）
3. **复制 zc_editor 到主仓**：`scaffolds/zc-editor-web-template/`
   - 精简版：去掉 node_modules、build 产物、业务 mock 之外的资产
   - 保留：源码骨架 + package.json（依赖指 `file:` 或镜像内 npm）+ vite.config / tsconfig
   - 在 .npmrc 配 ZC 包源（用上一步的 file:// 或 verdaccio URL）
4. **`scaffolds/registry.yaml` 注册** `zc-editor-web-template`

**关键风险**：现实 zc_editor 跑起来需要 ZC 后端接口（API mock）。底座精简到能不能脱离真实后端跑 dev server？需要保留 `mock/` 数据。

### 阶段 D：反向飞轮扩展支持 ZC Web 出码（2-3 天）

**目标**：用户创建反向飞轮任务时能选「ZC Web 模板」，pipeline 自动用新 sandbox 镜像 + ZC 知识桶。

**做法**：
1. **前端**：`CreateTaskModal.tsx` + `CreateMultipageTask.tsx` 加 template 选项「ZC Web (zc-editor)」
2. **backend**：
   - `scaffold_copier` 识别 `template_name=zc-editor-web-template` → 复制 `scaffolds/zc-editor-web-template/`
   - LLM 选桶逻辑加 `platform-zc-web` 桶（template_name 为 zc-* 时挂载）
   - sandbox 创建时指定镜像 `amis-ai-sandbox:zc-web-node20`（之前固定 `uniapp-node20`，改成按 template 路由）
3. **prompt**：ZC 模板的 system prompt 注入「使用 ZC 二开组件优先于原版 Amis 同名组件，二开点见 zc-amis-schema 桶」

### 阶段 E：评测 + 收尾（1-2 天，沿用 1.2 模式）

1. 写 2-3 个 ZC Web prompt（电商列表 / 后台 dashboard / CRUD 工单）
2. 用 `eval/multipage-1.2/runner.py` 扩展跑 ZC 模板 evaluation
3. 验收：task succeed_rate ≥ 90%（参照 1.2 100%）
4. release note：`docs/upgrades/2026-05-10-zc-amis-1.3.md`
5. PR 合 main + tag v1.3.0

## 5. 风险与权衡

| 风险 | 应对 |
|---|---|
| **ZC fork 二开点超预期多**（> 100 个） | 阶段 A 摸底后第一时间汇报，必要时缩 scope 到「只灌最常用 20 个组件」 |
| **ZC 包私有 nexus 网络不通时拉不到 .tgz** | 阶段 C 一次性下载完所有 tgz 备好，后续 sandbox build 不依赖网络 |
| **zc_editor 依赖 UmiJS / antd-pro / x6** | 体量大但都是公网 npm 包，应能正常 pnpm install；如果某个版本被锁 ZC 内网，再 .tgz 备 |
| **office-viewer 112 MB 必备吗** | 默认不打进 sandbox 镜像；如果 PDF/Excel 业务需要再 opt-in |
| **ZC 后端接口** | 底座保留 `mock/` 数据让 dev server 跑得起来；真实接口让 LLM 在 prompt 里生成 mock；上生产用户自己接 |
