## 二、1.4 候选方向（5 选 2-3 排序）

### A. **LLM 路由智能化**（Quality / Cost 双轴优化）
**痛点**：当前 auto 模式按 Amis JSON 复杂度选 model，但「复杂度」≈ schema token 数，粒度粗。
**方向**：
- 引入「任务难度评估器」前置 LLM 一次轻量调用，返回 difficulty/category 双标签
- 不同 category × difficulty 组合走不同 model（如 OA 复杂表单 → strong; 静态页 → fast）
- 引入「成本预算」：每用户 / 项目级 max-token 配额，超出降级
- A/B 框架追踪不同路由策略的 cost-per-success 曲线
**估时**：2-3 周
**前置依赖**：1.3 评测 baseline 数据（已有）

### B. **RAG 质量收口** （把 1.3 page-pass-rate 80% → 95%）
**痛点**：ZC 任务页失败的根因抽样后多半是 LLM 对 ZC 二开组件 prop 类型错配（如把 user-select 当原版 select 写）。
**方向**：
- 把 73 条 ZC 业务样例做「负例放大」：人工/自动改坏成「常见错误」版本，作为 RAG 负例
- LLM 评委（Phase 2/3）对每个 page 输出做「与 amis schema 是否对齐」打分，低分自动回流为 negative sample
- 增强 RAG 召回：从 amis JSON 关键字段（type/subTypes/api 协议）双路召回（精确 + 语义）
**估时**：2 周
**前置依赖**：1.3 评测 + 任务事件日志（已有）

### C. **Vue3 + Antd Pro X 模板**（覆盖 React 之外的 Web 主流栈）
**痛点**：当前 Web 端只有 `react-antd-vite-template` + `zc-editor-web-template`（也是 React），Vue3 用户全靠 `__blank__` 从零搭。
**方向**：
- 选定 `Vue3 + Vite + Element Plus / Naive UI / Antd Pro X` 之一（投票 / 用户调研）
- 移植 antd-pro 风格 dashboard 底座
- skill 桶补 `stack-vue3` references（当前只有 SKILL.md 顶层，无 references/）
**估时**：1 周
**前置依赖**：无

### D. **桌面端模板**（Tauri / Electron + 同套 amis 翻译能力）
**痛点**：客户偶尔问能不能出 PC 客户端，当前完全没覆盖。
**方向**：
- `scaffolds/tauri-vue3-template/` + `amis-ai-sandbox:tauri-rust-node20` 镜像
- 主进程 Rust，渲染进程复用 Vue3 + amis 翻译路径
- 评测增加桌面侧菜单 / 多窗口 / 文件对话 等场景
**估时**：3-4 周
**前置依赖**：C（如果选 Vue3 栈）

### E. **Skills Marketplace MVP**（让外部团队按标准协议接入 + 私有 RBAC）
**痛点**：1.2 引入了 `SKILLS_PLUGIN_PATHS`，但只支持挂载本地目录，无包管理 / 版本 / 发现。
**方向**：
- 定义 skill 包格式（tarball + manifest.json 含版本 / 兼容性 / 作者）
- 加 `/api/skills/marketplace` 列已发布包 + 安装命令
- 私有 nexus / S3 兼容存储 + 包签名校验
- RBAC：组织内私有桶 vs 公开桶
**估时**：4 周
**前置依赖**：1.3 Skills 标准协议（已有）

## 三、推荐路径

**最高 ROI 顺序**：
1. **B（RAG 质量收口）** — 直接拉升 1.3 用户体验，工作量适中
2. **A（LLM 路由智能化）** — 长期 cost 优化，结合 B 的评测 baseline 数据
3. **C（Vue3 模板）** — 覆盖 Web 端用户群体扩大

**1.4.0** scope（已拍）：**B + A + C** 三项一起进，总估时 5-6 周。

- **C 的 UI 库选型**：`Element Plus` ← 用户基数最大、文档最完整、amis 翻译适配难度最低；备选 Antd Pro X（Vue 版，保持和现有 react-antd-vite 风格统一）
- D（桌面端）/ E（Skills Marketplace）留作 1.5 候选

## 四、跨版本风险

| 风险 | 应对 |
|---|---|
| claw-agent-server 端 `default_skill_buckets` selector bug（1.3.2 已修，无 active impact） | 1.4 起新 skill 桶 frontmatter 显式标 `kind: platform` 强制走维度路径，避免依赖 template defaults |
| RAG 样例数据偏移（1.3 样例都是 ZC 业务，原版 amis-core 没涨） | 1.4 RAG 收口阶段同步扩 amis-core 样例（从 1.1 已灌的 148 条扩到 300+） |
| Vue3 / Tauri 桶引入后 conflicts 矩阵爆炸（priority 排序需要重新审） | 引入 「桶冲突测试」专项，每加新桶跑一遍冲突矩阵 |

## 五、不做的事

1. 不做 mobile-native（React Native / Flutter）—— 当前 H5 + 小程序覆盖率已足
2. 不做 LLM-as-judge 全自动 + 无人评测 —— 1.3 评测显示 LLM 评委对 ZC 二开组件 schema 的判断仍需人审兜底
3. 不做 multi-tenant SaaS 化 —— 仍是 self-hosted 工具定位，组织级权限到 1.4.E 即可
