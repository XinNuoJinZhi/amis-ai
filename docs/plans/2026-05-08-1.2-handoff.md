## ⚠️ 关键缺陷（next session 必修）

### 缺陷 1：「session 真完成」等待逻辑缺失（最关键）

**症状：** 跑 R1 e2e（5 页）显示瞬间 5 页全 done，但每页 started_at→finished_at 只差 64ms。

**根因：** [multipage_scheduler.rs](../../backend/src/services/multipage_scheduler.rs) 里 `run_isolated_pages_with_shared_context` 等 `claw-agent create_task` 返回 session_id 就立刻标 `status=done`。但 `create_task` 返回 session_id **只表示"session 已创建（LLM 异步开始跑）"**，不是 LLM 真跑完。

**修法：** 类似 1.0 单页路径的 [`spawn_dev_status_watcher`](../../backend/src/handlers/project_generation.rs)（line 763）那种思路 —— session 创建后，开 watcher 监听 sandbox dev_status 或轮询 claw-agent session 状态，直到真完成才标 page.status=done。涉及：
- `run_isolated_pages_with_shared_context`（W2.2 抽出的公共函数）
- `run_skeleton_stage` / `run_cleanup_stage` / `run_unified` / `run_r3_refactor`（5 处）

可参考 [`backend/src/handlers/project_events.rs`](../../backend/src/handlers/project_events.rs) 现有 dev_status 端点实现。

### 缺陷 2：时区混乱

**症状：** task=122 行里 `created_at` 是北京时间 `17:20:27`，`started_at` 是 UTC `09:20:33`，相差 8 小时。

**根因：** Rust 代码里 `chrono::Local::now().naive_local()`（北京）和 `chrono::Utc::now().naive_utc()`（UTC）混用，PG 列 TIMESTAMP 不带时区无法区分。

**修法：** 项目惯例统一用 `chrono::Utc::now().naive_utc()`（其他 entity / handler 都该统一）；前端展示再做时区转换。grep 找所有 `chrono::Local` 替换。

### 缺陷 3：e2e 脚本 jq null 守护

**症状：** R1 e2e 跑完报 `jq: error (at <stdin>:1): startswith() requires string inputs`。

**根因：** event 表里某些 event_type 是 NULL 或非字符串，`startswith` 不接受 null。

**修法：** 5 个 e2e 脚本里所有 `select(.event_type | startswith(...))` 改成 `select((.event_type // "") | startswith(...))`。

### 缺陷 4：闭环连线（plan 漏点）

**症状：** 任务跑完后没人调 `compute_reuse_rate` + 写 `reuse_metric` event + HTTP 调 agent `/multipage/record` 写 RAG。

**修法：** 在 `multipage_scheduler::dispatch` 函数末尾（5 种策略全跑成功后）加 epilog：
1. 调 sandbox HTTP `/sandboxes/:id/...`（W6.1 reuse_metrics 没暴露 endpoint，要补）
2. 写 `reuse_metric` event
3. 调 agent `POST http://localhost:8000/multipage/record`

或者在 backend 内联实现（避免跨服务 HTTP）：直接 fs 扫 workdir 算复用率。
